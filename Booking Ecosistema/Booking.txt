## 2. FUSIÓN — ¿CON QUÉ FRENTE SE FUSIONÓ?

**Botón Turismo NO aparece como frente separado en el Panorama K·C·T de 25 frentes.**

Originalmente era uno de los 33 frentes (Equipo 3: Botón Turismo / PAEM). En la racionalización 33→25, se fusionó operativamente con:

| Dimensión | Se fusionó con | Razón |
|-----------|---------------|-------|
| **Runtime** | **Pipeline / Gateway** (T) | Turismo corre como router dentro de `odi_api_gateway:app` en :8815. No tiene systemd unit propio ni puerto dedicado |
| **Conocimiento** | **ChromaDB / KB** (K) | Sus 27→89 docs dentales están en `odi_ind_salud_oral`, compartido con COVER'S |
| **Eventos** | **LiveODI Agent** (T) | Tourism events se emiten al LiveODI Agent WebSocket como source "turismo" |
| **Vertical** | **COVER'S / Salud Oral** (Tier 4 Multi-industria) | Comparte industria `salud_oral`, ChromaDB collection, y el bootstrap `detect_industry()` |

**En resumen:** Botón Turismo se absorbió en la infraestructura existente (gateway + KB + agent) en vez de mantenerse como servicio separado. Su lógica está en 4 módulos Python del core (`odi_tourism_*.py` + `odi_paem_orchestrator.py`) que se montan como router FastAPI en el gateway.

## 8. FLUJO COMPLETO DEL PACIENTE

```
1. Paciente llega (Widget o WhatsApp)
   → POST /api/tourism/intake
   → Lead en PG + audit SHA-256

2. ODI recolecta slots:
   Nombre → País → Procedimiento(s) → Diagnóstico previo → Contacto
   
3. ODI genera cotización 360°:
   → POST /api/tourism/quote
   → Procedimientos + logística + ahorro vs país de origen
   → Quote en PG + audit

4. Paciente decide:
   → Acepta → POST /api/paem/confirm → Booking con hold 15 min
   → Rechaza → Quote guardada 30 días
   
5. Post-confirmación:
   → Cron reminders (13:00 UTC)
   → Cron followups (cada 3h)
   → Cron expire-holds (cada 5 min)
   
6. Post-servicio:
   → NPS capture
   → Score < 7 → Detractor workflow (Piso 23)
```

## 9. APRENDIZAJES TÉCNICOS CLAVE

| Aprendizaje | Regla |
|-------------|-------|
| Timestamps SHA-256 | Siempre `.replace(tzinfo=None).isoformat() + "Z"` (nunca `+00:00`) |
| Metadata asyncpg | Pasar dict directo (nunca `json.dumps` — evita double-serialization) |
| Abandonment filters | Usar `created_at`, no `updated_at` |
| Ledger inmutabilidad | `tourism.events` rows NUNCA se borran; test data con `meta.is_test: true` |
| Deduplication | `doneTracked` ref previene eventos de conversión duplicados |
| CONFIRM_PENDING | Si PAEM real falló, NO marcar CONFIRMED — nuevo estado divergencia controlada |
| user_id convención | Contacto real del paciente (WhatsApp/email), no lead_id interno |
